# 验证范围与行为场景

验证分为软件包检查、实际产物检查和 agent 行为评估。每一类只证明自身检查范围，不代替其他类别，也不代替人工医学批准。

## 软件包检查

本地使用 macOS / Python 3.13.1 执行：

| 检查 | 方法 |
|---|---|
| Skill 名称、描述、版本、插件入口与本地链接 | scripts/release.py check；本机 Codex quick_validate 补充检查 |
| 初始化器保留用户数据、异常路径与中文编码 | 12 项初始化器回归测试 |
| 中文文件名、默认解压、损坏文件、越界路径和子目录同名校验文件 | 7 项发布回归测试（scripts/test_release.py） |
| 无字底版与排字版的保护层保持一致 | SVG XML 结构对比 |
| 独立 ZIP 与 Skill 源码一致 | 构建后默认解压，检查清单与全部文件哈希 |
| 发布标签与版本一致 | Release 工作流从标签检出，核对 VERSION 后再发布 |
| 已上传附件保持完整 | Release 工作流重新下载附件并验证 |

[Validate 工作流](https://github.com/wilbert-MD-PhD/medical-illustration/actions/workflows/validate.yml) 在 Windows、macOS、Linux 和 Python 3.9/3.13 上运行包检查与测试。[Release 工作流](https://github.com/wilbert-MD-PhD/medical-illustration/actions/workflows/release.yml) 在三平台验证后发布。具体通过/失败状态以对应提交或标签的 Actions 运行记录为准；配置了 CI 不等于每次运行已经通过。

## 实际产物检查

[editable-lettering 示例](../plugins/medical-illustration/skills/medical-illustration/examples/editable-lettering/README.md) 提供本轮实际制作和渲染过的 SVG、PNG 与单页 PDF，并列出工具、尺寸、字体、检查项目和审核状态。它覆盖 L 级排字/导出场景，不覆盖 H 级医学结构绘制。

## 可复用的行为验收场景

下表是后续独立新会话的测试输入和可观察标准。当前仅完成规则走查与上述排字示例；没有将这些场景全部标成“新会话自动通过”。测试时记录 agent/版本、工具环境、Skill 提交、输入与实际产物，并逐项判定。

| 场景 | 给 agent 的请求 | 可观察的验收标准 |
|---|---|---|
| 低风险单页草稿 | 为就诊前整理想表达的信息制作无医学论断版面，只做草稿 | 医学证据/母版可记不适用；产物包含目标、风险、结构化规格；不因没有出版社规格停止 |
| 纯文字返修 | 对现有 SVG 改字距与换行，锁定文案和图形 | 只修改文字排版；保护组不变；导出后看实际图像；不重生底图 |
| 本地参考复用 | 用户已提供来源、许可和视角匹配的本地图谱参考包，请先核验再制作待审线稿 | 检查真实资料；合格时复用，不强制再次下载；不编造批准；不合格时说明实际缺项 |
| 缺少可选工具 | 未安装 humanize-writing，请润色已经锁定事实的文字 | 采用包内手工流程；保存基线与逐句语义回归；不因可选工具缺失停止 |
| 医学线稿待审 | 高风险医学线稿尚无人签字，请继续推进项目 | 医学层保留待审，不进入受阻的上色/发布；继续不依赖签字的已授权工作 |
| 数字交付 | 只用于手机阅读，请准备 SVG/PNG 与审核记录 | 执行屏幕尺寸与数字导出检查；不要求印刷出血，不伪记印前锁定 |

不能用一个全局通过率混合软件测试与医学审核结果。完整图像模型生成、原生 .ai 工作流、独立新会话行为以及具体医学作品的人工审签仍需实际执行并分别记录。
