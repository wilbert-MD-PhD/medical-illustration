# 检查更新、更新与回退

本功能从 1.1.1 起提供，Python 3.9+，仅标准库。它管理独立 Skill 安装，不更新漫画项目、医学素材、字体、图像服务或 Illustrator。无需注册定时任务，也不在每次绘图时联网。

## 对话入口

| 用户请求 | 执行 |
|---|---|
| 检查医学绘图 Skill 更新 | `check`：只读安装版本、清单差异、备份及 GitHub 最新正式 Release |
| 更新医学绘图 Skill | `update`：未修改的独立安装直接下载、校验、备份、替换；保留用户已给出的授权 |
| 回退医学绘图 Skill | `rollback`：恢复上一次操作前的完整备份，同时备份当前版本 |

先从宿主提供的 Skill 路径确认**实际加载的安装目录**，显式传 `--install-dir`。不凭最高版本或目录名称选择目标。不指定时仅在已发现唯一副本时使用；多个候选会报错列出位置。候选扫描覆盖个人及当前项目祖先的常见技能目录，不能证明发现所有宿主缓存或实际加载状态。

## 命令

`<更新器>` 是当前 Skill 或已校验新包内 `scripts/update_skill.py` 的绝对路径；`<安装目录>` 是实际加载的整个 `medical-illustration` 文件夹。路径含空格时保留引号；Windows 可用 `py -3` 替代 `python3`。

```bash
python3 "<更新器>" check --install-dir "<安装目录>"
python3 "<更新器>" update --install-dir "<安装目录>"
python3 "<更新器>" rollback --install-dir "<安装目录>"
```

输出为 JSON：检查返回本地版本、`clean/modified/unknown`、差异文件、已发现副本、可回退 ID 及远端版本。未知旧版的 `version` 和 `update_available` 为 `null`，不能解释为已是最新。网络/API/附件失败返回非零退出码，不把失败当成没有更新。

默认 `/releases/latest` 仅选正式公开发布，要求独立 ZIP 和同名 `.sha256` 都存在。需指定版本时用 `--version 1.1.1`；RC 需明确版本并加 `--allow-prerelease`。不自动降级、跟踪 main 或安装草稿版本。显式选择本地包时由调用者确认其版本及来源。

匿名 GitHub API 返回 403/429 时，自动尝试 PATH 中已安装且已登录的 GitHub CLI（可选依赖），通过固定 github.com 仓库只读查询。输出 metadata_source 区分 github-api 与 gh-cli。不读取或输出令牌，不自动启动登录，禁用交互提示及认证调试日志；CLI缺失、登录失效、超时或仍被限流时明确报错并保留原安装，可稍后重试或使用离线包。其他HTTP错误不使用该回退。

离线检查及用已经取得的完整发布包更新：

```bash
python3 "<更新器>" check --offline --install-dir "<安装目录>"
python3 "<更新器>" update --install-dir "<安装目录>" --archive "<独立安装包.zip>" --sha256 "<独立安装包.zip.sha256>"
```

在线取得包时使用固定项目的 GitHub Release 附件及 HTTPS，核验 ZIP 的 SHA-256、解包路径、完整目录、内部 SHA256SUMS 与标签/VERSION；不执行下载包中的代码来验收。校验和用于核对完整性，不等于独立数字签名。大小限制为压缩包 25 MB、展开 100 MB、5000 项。

## 本地改动与旧版本接入

- `modified` 会列出 changed/missing/extra；`unknown` 表示无有效校验清单。缺少 VERSION 的安装仍可识别为本 Skill，但版本保持未知，不猜测版本号。
- 更新默认拒绝替换这些目录。向用户展示检查结果和“完整保留旧版，但新活动目录不自动合并这些修改”的具体影响；用户已明确选择这种处理时直接继续，否则请其选择保留等待合并或备份后替换。不要先运行首次安装器、删旧目录或强行加开关。
- 用户明确选择后，在更新命令后加 `--replace-local`。旧目录连同自定义文件完整保存在备份中，不会消失；它们不会自动出现在新活动目录。需要继续生效的修改按实际差异另外合并，合并后登记为本地修改。
- **1.1.0 及以前没有此脚本，无法靠旧 Skill 自行获得更新器。** 首次从实际已发布的 1.1.1 或更高完整包取得脚本，核对下载来源和包校验值后，在包外部调用它并用 `--install-dir` 指向旧安装。同一次操作会将包含更新器的完整新版装入目标，以后直接使用内置入口。本地尚未发布的源码不能宣称可供远端用户下载安装。
- 没有有效基线的旧目录可能包含用户修改，不能因文件看起来正常就宣称无改动。原有项目模板保持原位，不运行初始化器来“迁移”旧项目。

## 备份、失败与回退

备份位于安装目录上两级下的 `.medical-illustration-updates/<安装路径哈希>/<备份ID>/previous`，在常规 `skills/` 扫描目录之外。每次返回准确 `backup_dir`，不会创建另一个可用同名 Skill 或旧路径替身，也不自动删除历史备份。

更新器使用每个安装的排他锁，替换前复核原目录全部文件哈希，用同一文件系统的目录重命名完成切换；新目录再次核验。运行时不要同时编辑目标目录或让另一个安装器更新它。捕获到替换失败时恢复旧目录；回退也先备份当前目录，原备份仍保留。

`check --offline` 列出可用备份；默认回退到最近一次成功操作之前，也可指定 `rollback --backup <ID>`。备份被修改会拒绝恢复；当前安装在上次操作后产生改动时，回退同样需用户选择后再加 `--replace-local`。

进程被强杀、断电及磁盘故障不保证自动恢复。若存在旧锁或 `recovery-required`，不自动清锁或重投：先核实原进程已结束，读取对应 `transaction.json` 并对照 before/after 哈希、`previous`、当前目录及 `failed-new-copy`。保护现存各份内容后恢复原目录；恢复失败时保留原锁与确切备份路径并报告。不要把文件仅存在当成已恢复成功。

## 刷新与边界

完成后检查目标目录的 VERSION 与输出的实际路径，在宿主刷新技能或新任务中显式调用；必要时按宿主方式重启。只有看到实际加载的新路径/版本才能说“宿主已加载”；更新器仅能报告磁盘验收，输出 `host_reload` 提醒。

Marketplace/插件缓存中的安装由宿主管理，本脚本会拒绝替换；有插件元数据不表示已实测其更新功能。不要绕过此限制修改缓存。对用户明确管理的独立安装，已有更新授权无需再次询问；真实权限限制仍通过工具的正常权限机制处理。
