# 首次环境检查与开始制作

目标是验证当前使用者的环境能否完成具体任务。安装完成与制作就绪分别报告，不承诺所有 Codex 账号或运行方式都包含同一组工具。

## 1. 验证 Skill 安装

读取实际安装位置的 VERSION、SKILL.md 和 SHA256SUMS，检查清单中所有文件的 SHA-256 与相对资源。确认没有同名旧版本干扰加载。安装器会拒绝覆盖已有同名目录；更新时先记录实际路径，保留使用者的改动，再根据已授权范围更新。

下一轮显式调用 `$medical-illustration`，未刷新时重启 Codex。读取文件进行安装验收不等同于已经确认新技能被运行环境发现。

## 2. 按能力检查与补齐

| 能力 | 首选 | 缺失时的处理 |
|---|---|---|
| 项目初始化 | 当前 Python 3.9+，只用标准库 | 先找 Codex 自带运行时；仍无 Python，可手工建立模板，或按平台官方安装方式补齐 |
| 图片生成 | 当前会话实际可调用的图像工具 | 检查工具清单及对应使用说明；仅有 imagegen Skill 文本不等于有图像工具。需要用户登录、启用服务或配置本地环境变量时明确说明 |
| 中文字体 | 已安装且覆盖所需汉字的字体 | 核验真实字体文件及许可；可从思源黑体、Noto CJK 或霞鹜文楷的官方项目获取并按平台安装，保留许可；不依赖作者电脑字体名称自动存在 |
| 可编辑排字 | Illustrator，或真实保留文字对象的 SVG/矢量工具 | 可直接生成分层 SVG，并在能正确加载中文字体的浏览器或矢量工具中检查；避免把整页转成图片冒充可编辑文字 |
| PDF 导出和页面检查 | 可用矢量工具或浏览器的 PDF 导出及页面渲染能力 | 若现有工具不足，按下方免费 Python 路径补齐；必须实际导出并查看页面，不能只检查命令是否存在 |
| 医学依据和审稿 | 用户资料、可核验来源、项目实际审核人 | 资料不足先做可核验范围的分镜或非医学表现层；按内容风险分别记录制作和人工待审状态 |

不要批量安装所有相关 Skill、3D 软件或商业软件。`humanize-writing` 与 `baoyu-comic` 缺失时使用包内流程。只有当前任务确有缺口，才从官方来源补齐所需组件。

### 免费 Python 导出路径（需要时）

优先复用当前运行时已有组件。需要新依赖时，在漫画项目内创建专用虚拟环境，用该环境的 Python 安装 `reportlab` 和 `Pillow`；它们用于文字/PDF 和图像读取，不提供图像生成服务。安装前核对官方文档与当前 Python 兼容性，记录实际安装版本；不要修改系统 Python 或无关项目环境。

macOS/Linux 的环境 Python 通常在 `.venv/bin/python`，Windows 在 `.venv\Scripts\python.exe`。以实际创建路径为准。若 PDF 渲染工具缺失，可使用已具备的浏览器、系统预览或按对应官方说明安装 Poppler。使用中文字体时选所用导出器实际支持的字体文件；仅看到一个字体家族名称不算验收通过。

## 3. 最小实际验收

1. 在临时目录运行初始化器，运行两次，确认现有文件未被覆盖。
2. 制作一张含“医学科普漫画：中文排字测试”的独立文字层，导出 SVG 与单页 PDF。
3. 实际打开或渲染 SVG 和 PDF，检查汉字、换行、文字边界；保留可编辑文字对象和使用字体记录。
4. 检查当前图像工具。优先使用本次会话已有成功调用作为证据；否则，在符合使用者授权和费用范围时生成一张无医学内容的小型测试图。未实际调用成功只能记为“工具已发现，生成未实测”。
5. 逐项报告通过、未实测或缺失，以及具体文件路径；依赖安装不能代替上述结果。

验收图像不包含解剖、查体、康复动作或临床建议，不冒充医学作品审签。

## 4. 收集需求后制作

沿用用户已给出的主题、目标读者和范围，仅缺少会实质影响制作的信息时询问，再按 [SKILL.md](../SKILL.md) 的工作模式推进：页面目标、证据与分镜、文字空间规划、彩色无字画面、正常字号试排及独立可编辑文字/气泡层、PDF 审阅稿。仅缺印刷规格时继续数字草稿。医学事实层需要合格参考和适用审核；依据不足不通过自由生成补齐事实。

人工未签可继续已授权制作，保持医学待审；医学作品正式发布按当前项目要求落实适用审核。无字底板、SVG 和 PDF 分别保留，用户要求的原生 .ai 需单独验证，不能用改后缀代替。
